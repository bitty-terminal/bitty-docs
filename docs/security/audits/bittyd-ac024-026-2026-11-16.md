# bittyd MCP/Agent, DevTools, and Trace Evidence 2026-11-16

**Status: dated evidence record; independent review pending.** This record
supplies the cells the three criteria could decide on the served daemon:

- `P0-AC-024` — the Agent/MCP read-only default, the untrusted-observation
  label, and "no connection holds a write authority implicitly";
- `P0-AC-025` — the DevTools scope family is distinct and a connection alone
  grants none of it, with the typed refusal code at both layers;
- `P0-AC-026` — trace minimization and redaction, observed at the audit write
  point and against a seeded-secret corpus.

No criterion is marked Verified and no risk state moves. All three stay
**Partially verified**: the MCP/Agent adapter audit and the instruction/data
channel-separation review are `bitty-ai`/adapter-owned and absent, the daemon
serves no DevTools endpoint and no trace/export surface at this revision, and
no independent reviewer has signed off. The evidence-matrix rows `R-011`..`R-014`
and the daemon-intake rows `DR-01`..`DR-08` stay `Open`.

## Purpose

The criteria, quoted from [`p0-acceptance-criteria.md`](../p0-acceptance-criteria.md):

```text
P0-AC-024  Given an MCP/Agent client without elevation, when it operates, then
           only read-style operations succeed; every response containing
           terminal content labels it untrusted observation data; sending
           input, spawning processes, installing plugins, or writing
           configuration requires per-client consent and cannot be combined
           automatically with filesystem/network authority.
           Pass threshold: default-deny matrix passes; labeling asserted in API
           responses and confirmed by auditor review of the instruction/data
           channel separation.

P0-AC-025  Given a DevTools client that has merely connected, when it attempts
           debug.inspect, debug.trace, or debug.control, then each is denied
           until separately granted.
           Pass threshold: three-scope matrix shows connection alone grants none.

P0-AC-026  Given traces, diagnostics, and crash reports generated during normal
           use, when written locally, then typed sensitive fields are redacted,
           input recording is off by default and opt-in, clipboard and raw
           environment data are absent by default, files carry user-only
           permissions, and export previews show exactly what will be uploaded.
           Pass threshold: seeded-secret corpus never appears in default
           outputs; file mode 0600 asserted; export preview equals actual export
           byte-for-byte.
```

The two new tests drive `AuditSink::record` with a capturing `AuditWriter`, so
the assertion is on the bytes the sink hands its writer, not on the record type:

- Six seeds shaped like a cloud access key, an API key, a forge token, a private
  key header, a URL with an inline password, and a bearer token are rendered
  through a maximal record (refused result, session counters, actor facts,
  aggregate, terminal transition). Every rendered line carries the opaque
  digest and contains neither the seed nor any 6-byte window of it.
- The sink's line is byte-for-byte `render_record`'s output for the same
  record, and its key list is the closed 26-key vocabulary in emit order
  (`ev t i a r c s g rv u p cid x k d ca cl m sup bl h ho z zr zc zk`). Every
  value is ASCII alphanumeric plus `_.:,-` only: no `/`, no whitespace, no
  second `=`, no non-ASCII byte. A path, an argv element, an environment
  value, a message, or a token is therefore unrepresentable at the write point,
  not merely absent by convention.

The live cell seeds every client-controlled field a `session.create` accepts —

whose directory name carries a seed, the idempotency key, and the
`client_correlation` value — then reads the segment:

## Residuals

- **Independent security review: pending.** Nothing here is Verified. A record is
  evidence for review, not the verdict; `R-013` and `R-014` stay `Open` and the
  three criteria stay `Partially verified`.
- **The MCP/Agent adapter audit is absent.** `P0-AC-024`'s labeling half is now
  observed at the daemon boundary, but the adapter that turns daemon content
  into an agent-visible message (`bitty-ai`, `bitty-ipc-mcp`) was not audited
  here, and the instruction/data channel-separation review the criterion names
  has no author. The live cells exercise the daemon's `session.read` plane only.
- **The confused-deputy suite is absent.** No hostile-output replay shows an
  instruction embedded in terminal bytes failing to reach an action channel;
  the label makes that testable but does not perform it.
- **No DevTools endpoint exists.** `P0-AC-025` is a matrix-and-catalog result
  plus a live `NotFound`. A live DevTools client, a granted `debug.*` scope on a
  served surface, and the formal DevTools scope audit remain unrun because the
  daemon serves no such method and no scope-granting path for it.
- **The trace surface is not served.** Trace start/stop/fetch, the export
  preview equality, the crash-report scan, and the formal trace-minimization
  audit live in `bitty-ipc-devtools` and are not reachable from `bittyd` at this
  revision. `P0-AC-026` therefore stands on the audit write point and the live
  audit segment, not on a trace record.
- **Input recording and clipboard are unexercised**, for the same reason: there
  is no input-recording control and no clipboard read in the daemon's catalog.
  The criterion's "off by default" half is not contradicted, it is not run.
- **The `1.85` MSRV and clippy gates were run on the change, not on the record.**
  They are listed in the PR body rather than here; this record adds no code
  beyond tests.
- **Second-uid and non-Linux cells remain unrun**, as every prior record says: no
  second local account and no passwordless escalation on this host, no Windows
  named-pipe cell.
